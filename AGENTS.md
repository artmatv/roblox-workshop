# Правила разработки Roblox Automation

- Ведущий разработчик и приёмка: GPT-6.1 Sol, effort medium.
- Код по конкретному ТЗ: GPT-6 Luna, effort medium. Sol задаёт область изменений и проверяемые критерии, затем принимает результат.
- GPT-6 Astra, effort medium: только проектирование и независимая проверка архитектурных решений; не редактировать и не генерировать программные исходники.
- Мультиагентная работа разрешена для ограниченных задач. Один владелец изменяет живую сцену Studio; помощники работают с локальными исходниками или возвращают разбор.
- Для обычной разработки не повышать effort автоматически после ошибок; сначала исправить постановку или конкретную причину.
- KISS и YAGNI: реализовать только запрошенное. Использовать существующие функции и один основной путь выполнения.
- Не добавлять фреймворки, новые слои, альтернативные реализации, дубли кода, ветки/worktree, тестовые среды или резервные копии без конкретной необходимости.
- Сохранять существующие игровые данные и согласования. Сохранение результата и необходимая проверка восстановления не являются необязательным усложнением.
- Для небольшой задачи достаточно короткого ТЗ и критериев приёмки. Не создавать формальную иерархию этапов и документы ради процесса.
- Перед существенным изменением архитектуры запросить независимый разбор Astra. Обычная локальная правка не требует нового архитектурного этапа.
- Проверять изменённое поведение подходящими существующими проверками. Не дублировать проверки и не запускать их повторно без причины.
- Визуальное качество игры подтверждать настоящими кадрами Studio и оценкой композиции. Успех тестов не означает хороший дизайн.

- Правило владельца от 2026-11-04: все исправления игр выполнять только через задачи мастерской. Управляющему ассистенту вне очереди нельзя напрямую менять Studio или игровые исходники; агент действительно запущенной задачи мастерской использует её контролируемые инструменты по назначению. Прямой доступ — только для чтения, диагностики и просмотра. Если мастерская не справляется, исправить её механизм и повторить задачу через неё. Подробности: PROJECT_NOTES.md.
