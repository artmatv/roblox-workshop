## Восстановление доступа в браузере

Сообщение с предложением запустить Start.ps1 показывалось при потере sessionStorage-токена в новой вкладке. При воспроизведении `/health` уже возвращал status=ok: сервис был запущен, а проблема находилась в авторизации браузера. Ранее любой отказ API также отображался как проблема запуска.

После доверенного первого открытия браузер получает подписанную HttpOnly/SameSite=Strict cookie на 30 дней с Path=/api и привязкой к ключу/порту сервиса. Новая вкладка и повторно открытый браузер подключаются без sessionStorage-токена. Корневой токен не хранится в cookie и не переносится в localStorage. Анонимные, поддельные, истёкшие и cross-site запросы остаются закрыты; cookie дашборда не авторизует Studio bridge. В UI различаются отсутствие доступа, ошибка сервиса и сетевой разрыв с автоматическим повтором. Личная ссылка обрабатывается также при hashchange в уже открытой вкладке.

`npm run verify`: **61 тест проходит**, TypeScript/Vite собраны. Новый HTTP-сценарий проверяет повторный старт сервиса, восстановление по cookie, запрет неподтверждённого доступа и сохранение границ Host/Origin/bridge. В настоящем браузере пройдены: неподтверждённая страница → личная ссылка в той же вкладке → закрытие вкладки → обычный адрес в новой вкладке → закрытие и повторный запуск браузера → искусственный обрыв сети → автоматическое восстановление. Доступ восстановился при пустом sessionStorage; ошибки страницы отсутствуют. Никакие агенты или команды Studio не запускались, данные проекта сохранены. Отчёт: [browser-session.json](verification/browser-session.json), снимок: [browser-session-restored.png](verification/browser-session-restored.png).
