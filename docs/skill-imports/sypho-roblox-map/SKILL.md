# Карты Roblox: планирование и офлайн-проверка

# Адаптация SyphoDev для мастерской

Выборочная адаптация исходного навыка для Roblox Automation. Точная неизменённая upstream-версия находится в UPSTREAM.md. Исходники в resources/ являются справочными; запускать их только в workspace активной native-задачи с отключённой сетью.

## Граница изменений

Изменять игру может только агент действительно запущенной задачи мастерской и только через её контролируемые инструменты. Соблюдать очередь, утверждённые стиль, механики и данные проекта. Не обходить очередь, не публиковать автоматически и не выполнять платежи. В одном проекте должен быть один Studio writer. Не использовать .claude/, Claude agents/orchestrators, LOCAL.md, model roster, sessions, отдельные очереди, установщики или внешние генераторы, Cloudflare, Kaggle, Pollinations и их ключи.

Офлайн Python запускать только внутри workspace активной native-задачи с отключённой сетью. Изменения сцены и проверки в Studio выполнять только через контролируемые workshop MCP вызовы этой задачи. Не запускать произвольные Studio команды из shell.

## Карты: офлайн-проверка и передача в Studio

Для задачи design/spec без bound Studio или вне native workspace только зафиксировать требования и непроверенные допущения; пока не запускать скрипты. Использовать Python-ресурсы только в workspace активной native-задачи с network=false. Получить актуальные geometry и movement numbers из задачи и Studio; не подменять их демонстрационными профилями. Для Python нужны numpy, scipy и Pillow. Использовать обычные parts и встроенный stairs: custom kits требуют отсутствующий kit.py и не входят в эту адаптацию. Поток: spec -> prove/plan -> emit. PASS означает только прохождение статических/геометрических проверок модели; он не доказывает живую физику, достижимость в игре или визуальную красоту.

Сгенерированный результат передавать только через предусмотренную задачу мастерской. Любые проверки и изменения в Studio выполнять только её контролируемыми вызовами workshop MCP.

См. `TOOLING.md` для локальных offline entrypoints и `resources/` для сохранённых upstream-файлов.
