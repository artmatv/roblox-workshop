# Подключение навыков Sypho

В мастерскую импортированы три навыка из upstream commit `5aad881d1e6553cc3671ad549fdf01b8191bdc37`; закреплённая локальная версия пакетов обозначена суффиксом `-workshop.1`. Это `sypho-roblox-map`, `sypho-roblox-sfx` и `sypho-roblox-ui-tools`; пакеты включают соответственно 27, 8 и 18 файлов. Их описания и сведения о составе находятся в `docs/skill-imports/`.

Эти дополнения расширяют шесть уже установленных навыков, а не заменяют их:

| Уже установлено | Что добавляют навыки Sypho |
|---|---|
| `game-ui-ux`, `roblox-ui` | `sypho-roblox-ui-tools` добавляет машинные проверки геометрии, touch/fit, labels и wiring; дизайн и основной UI workflow остаются за установленными навыками. |
| `roblox-luau`, `roblox-datastores` | Прямой замены нет: эти навыки по-прежнему отвечают за Luau и сохранение данных; Sypho-пакеты не меняют их область. |
| `create-game-assets` | Прямой замены нет: он остаётся для планирования и создания визуальных ресурсов. |
| `roblox-ui-styles` | Дополняет выбор и применение стиля: Sypho UI tools проверяют макет, но не навязывают тему или редизайн. |
| — | `sypho-roblox-map` добавляет планирование карты, проверку достижимости и terrain helpers. |
| — | `sypho-roblox-sfx` добавляет поиск звуков, проверку загрузки/длительности и офлайн-генерацию банка. |

Итого: три новых pinned package для map, SFX и UI tooling; шесть прежних остаются назначенными и сохраняют свои роли.

В начале native-задачи `skills/ACTIVE.json` перечисляет каждый текущий pin, включая `instructionPath`, `root`, `packageHash` и ресурсы. Пути ведут в уникальное поколение внутри task workspace: инструкции — `skills/instructions/<id>/<hash>/<generation>.md`, ресурсы — `skills/packages/<id>/<hash>/<generation>/`. Агент должен использовать пути именно из индекса; повторно использовать старые материалы задачи нельзя.

Офлайн Python-библиотеки хранятся на стороне сервиса в `data/python-runtime` (NumPy 2.4.3, SciPy 1.18.1, Pillow 10.4.0). При старте задачи мастерская копирует их в уникальный `.tool-runtime/python-<generation>` внутри её workspace и устанавливает `PYTHONPATH` на эту task-local копию, `PYTHONNOUSERSITE=1` и `PYTHONDONTWRITEBYTECODE=1`. Shell запускается с отключённой сетью. Это важно: агент не видит пользовательский Python site-packages или общую папку библиотеки. Устанавливать пакеты через pip или подключать новые сервисы не нужно.

Проверки навыков включают map и terrain self-test, план/генерацию карты, SFX поиск через `workshop.search_sfx`, отдельное измерение `IsLoaded`/`TimeLength` в Studio и офлайн-конвейер `pick.py` → `emit_bank.py`. Для Studio SFX и сравнения сцены доступны только фиксированные host tools `workshop.probe_sfx` и `workshop.validation_control`: они не принимают исходный код или произвольные пути и сами подтверждают выбранные из поиска IDs, измерения, очистку task-specific временной папки, fingerprint сцены и состояние симулятора. Diagnostic profile не использует `execute_luau` для этих доказательств. Банк проверяется на совпадение фактического выбранного ID; `install.lua` и опасный upstream probe, очищающий `SFXProbe`, не запускаются. UI-инструменты проверяются на self-test, touch/fit и labels. Свежие desktop/mobile кадры помогают оценить результат на существующем проекте. Для `verify_map.py` запускается один self-test без `--help`, поскольку `--help` всё равно запускает self-test из 11 случаев; `checks_terrain.py --selftest` выполняется один раз. Справку других CLI проверяют только при необходимости, а известные точные команды повторно ради справки не запускают. Офлайн-доказательство не подтверждает физику игры, а прохождение автоматических проверок не означает готовность всей игры.

После первой попытки выяснился блокер профиля: задача `6c59eed1-bde7-4dee-8206-8bbe71601f28` завершилась со статусом native `succeeded`, но проверка профиля была `blocked`. Эти статусы не следует смешивать; её сводка и отчёт сохранены в `data/native-runs/6c59eed1-bde7-4dee-8206-8bbe71601f28/skill-validation-summary.json` и `skill-validation-report.json`. Причина была в недоступности общего Python runtime из изолированного task workspace; runtime теперь копируется в задачу описанным выше способом.

Финальная ограниченная диагностика `8296649a-36bc-46e0-af95-d3796054cdcc` завершилась со статусами task `succeeded`, profile `passed` и всеми 16/16 gates. [Сводка проверки](../verification/sypho-workshop.json) указывает task-specific report и пять свежих кадров; [integrity report](../verification/sypho-integrity.json) подтверждает совпадение хешей всех 53 файлов навыков, неизменность project revision/stage/settings/approvals/skill pins, восстановление execution decision и предыдущей native session, освобождение validation context и совпадение scene fingerprint (`4cc7edcd…ac124d01`). Тело отчёта и пять кадров сохранены и проверены на неизменность. Независимый reviewer получил только JSON отчёта: это текстовая проверка, не визуальная приёмка игры. Её пробелы по сырым доказательствам root отдельно сверил с host trace, реальными файлами и изображениями; проверил в том числе намеренный negative FAIL, Lua output с зафиксированным хешем (не исполнялся), task-local Python версии и фактические before/after host records. Кадры, включая shop, collection и mobile HUD, просмотрены отдельно. Общий набор тестов: **195/195** ([лог](../verification/sypho-test-run.txt)); `npm run check` и Vite build прошли.

Предыдущие попытки завершились отдельно и не считаются текущими. История блокеров: task-local Python runtime сначала был недоступен; другой запуск был заблокирован неполным prompt (не были перечислены 16 gate IDs) и формой host measurement evidence; отдельный запуск прошёл gates, но общий результат ошибочно отклонили из-за трактовки `storedPath`; ещё один завершился с 15/16, поскольку shop кадр показывал HUD. Более ранний запуск отменили после visual review clipping существующего мобильного интерфейса. Финальный запуск использовал фактические `files[].path` и уточнённые правила кадров. Игру в рамках диагностики не меняли.

Отрицательные fixture проверки намеренно должны возвращать FAIL, а минимальный план карты может содержать WARN; такие результаты остаются обозначенными как отрицательные/предупреждения и не переименовываются в PASS. Офлайн proof не доказывает физику в игре, человеческое прослушивание звука не выполнялось (`humanListening: not_run`), а тяжёлые проверки 3D, анимации и VFX отложены.

Владелец задачи запретил редизайн, постоянные игровые изменения, новые арт-ассеты, покупки и публикацию. Новые платные сервисы подключать нельзя; существующая настроенная независимая проверка остаётся под контролем мастерской и её бюджета. Все проверки и изменения игры выполняет только запущенная задача через контролируемые инструменты мастерской.
