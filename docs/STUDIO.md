# Подключение Roblox Studio

Плагин: `plugin/Automation.rbxmx`. Исходник: `plugin/Automation.plugin.luau`. Пересборка пакета: `node scripts/build-plugin.mjs`.

## Установка и привязка

1. Откройте отдельный пустой проект Studio для проверки. Существующие игры используйте только после сохранения исходной копии и выбора именно этого проекта в дашборде.
2. Поместите `Automation.rbxmx` в локальную папку плагинов Studio, которую Studio открывает командой **Plugins Folder**. При необходимости перезапустите Studio.
3. Откройте панель «Мастерская» через вкладку Plugins.
4. В дашборде нажмите «Код подключения». Код действует пять минут и используется один раз.
5. В плагине укажите `http://127.0.0.1:4317`, введите код и нажмите «Подключить». Если Studio запрашивает доступ плагина к localhost, решение принимает пользователь.
6. В дашборде выберите показанное подключение. Сверьте имя, PlaceId и проект перед привязкой. Только после этого сервис отправляет команды.

У каждой работающей Studio отдельный идентификатор подключения. Плагин не содержит OpenAI ключей. Его токен позволяет только получать задания и отвечать за своё подключение. Кнопка «Остановить» приостанавливает проект и приём новых изменений.

Во время Play плагин продолжает подтверждать соединение через `/bridge/poll` с `playing=true`, но сервис не выдаёт команды. Режим определяется `StudioTestService.EditModeActive`. После остановки Play очередь продолжается. Дашборд показывает живой режим и последнюю связь; сохранённая привязка сама по себе не означает активное подключение. Отвязка в обзоре проекта очищает выбранный проект и в плагине.

Этот сценарий проверен на **установленном локальном Automation.rbxmx** с вводом кода в его собственную панель: [product-flow.json](verification/product-flow.json). Временный загрузчик PluginManager при переключении Play не воспроизводит жизненный цикл установленного плагина и для этой проверки не используется. Открытый сейчас Place1 сохранён в `docs/verification/Place1.rbxl`; это исходные Baseplate и SpawnLocation, без сгенерированной игровой сцены. Его подключение можно выбрать для нового проекта из дашборда.

## Команды

| Операция | Поведение |
| --- | --- |
| snapshot | Чтение дерева, поддерживаемых свойств и исходников. Доступно и при конфликте |
| apply | Применение проверенного manifest; резервная копия затрагиваемых объектов и запись ChangeHistory |
| restore | Восстановление manifest как новой версии, со сбросом проверок |
| test | Временный Studio-only runner, Play/Multiplayer через StudioTestService, результаты и логи |
| capture | StudioCaptureService, PNG через localhost; при отсутствии разрешения — ошибка |
| import | InsertService.LoadAsset; скрипты из внешнего ресурса удаляются; модерация и разрешение experience остаются неподтверждёнными |

Проверки UI выполняются в конфигурациях 1366×768 и 390×844 через StudioDeviceSimulatorService. В конце восстанавливается предыдущее устройство или выключается симуляция. Это не замена реальному телефону. Сценарий игры должен действительно проверять UI, сетевой режим и сохранения; наличие объекта само по себе не доказывает игровой результат.

QA ModuleScript `ServerStorage/AutomationTests` экспортирует `run(args)` и возвращает `{checks={...}, findings={...}}`. Проверка содержит `id`, `name`, `required`, `status`, `evidence`. Таймаут — 90 секунд на запуск. Основные обязательные ID перечислены в `server/engine.ts`. Отдельная проверка предпросмотра стиля использует `style-runtime`.

## Конфликты и потерянный ответ

Перед записью плагин сравнивает ревизию и отпечаток сцены. Неожиданная правка вызывает отказ. Запросите новый snapshot и либо примите его отдельной версией через дашборд, либо сохраните исходные правки и выберите восстановление. Снимок не обновляет базу молча.

Ответ о завершении сохраняется в настройках плагина до отправки. После сбоя соединения повторяется отправка ответа, а не сама операция. Если завершение осталось неопределённым, очередь блокируется до сверки. Не помечайте операцию неуспешной без просмотра фактического состояния.

## Ограничения протокола первой реализации

Manifest поддерживает стандартные скрипты и Instance, примитивные свойства, Vector2/3, Color3, CFrame, UDim/UDim2, Enum и Content. Для XML числовой token берётся из проверенного справочника Enum; неизвестное или противоречащее ему значение отклоняется. Корневой Lighting поддерживает Brightness, ClockTime, Ambient, OutdoorAmbient, FogColor, FogStart и FogEnd; остальные эффекты задаются дочерними объектами. Неподдержанные свойства сервиса отклоняются до отправки команды. Ссылки Instance между объектами, Terrain voxels, EditableMesh/Image, произвольные sequences и движковые бинарные ресурсы пока не сериализуются. Используйте процедурные стандартные Parts и код, либо подключайте отдельный проверенный адаптер; не объявляйте неподдержанный ресурс готовым.

На согласованном Place1 проверены localhost, применение сцены, реальные Play/Multiplayer запуски, два эмулируемых устройства, повторная доставка результата после перезапуска сервиса, восстановление привязки и откат. Тот же исходник выполнялся через временный PluginManager; загрузка устанавливаемого .rbxmx отдельно проверена в новом окне Studio. Самостоятельному screenshot-адаптеру разрешение не выдано; снимок отчёта сделан через Studio MCP.

Плагин установлен в `%LOCALAPPDATA%\Roblox\Plugins\Automation.rbxmx`. Для уже открытого редактора может понадобиться перезапуск Studio. После первой привязки сохраняются scoped credentials конкретного документа; следующие сессии восстанавливают проект и ревизию. Активное другое окно, смена experience или неопределённая отправленная операция блокируют автоматический перенос привязки. Исходный отпечаток не заменяется новым молча.
